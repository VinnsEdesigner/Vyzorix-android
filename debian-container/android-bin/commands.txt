# The human command surface for the bridge APIs.
#
# This file is the source of truth for *what an operator types* in the container's
# shell. It is deliberately separate from `apis.txt`, which is the *wire* surface:
# the API name the router serves, the catalog the binary prints, the name the server
# tags. The wire name is a contract with the server and the tests, so renaming it to
# make the CLI nicer would ripple through all of that for no gain; the human name is
# free to be terse.
#
# `commands_test` (tests/android-core) fails if this file and `apis.txt` disagree, so
# a new API cannot ship without a command and a command cannot point at no API.
#
# Format:  <wire api name>  <command> [subcommand]
#
#   * one column  -> a top-level command of that name (`wallpaper`, `battery`)
#   * two columns -> `command subcommand` (`bt ctrl`, `admin action`)
#
# The generator emits one symlink per *command* (not per API) plus a dispatch table,
# and `android-bin` resolves `argv[0]` + `argv[1]` to the wire name. A top-level
# command with subcommands still accepts `--api` for the raw name.
#
# ## Naming rules the list follows
#
#   * Terse where Linux is terse; no underscores.
#   * Never shadow a real binary: `/usr/local/bin` precedes `/usr/bin`, so a command
#     named `ps`, `locale` or `sensors` would break the real one. Hence `procs`, `lang`,
#     `sensor`.
#   * Never use a shell keyword or builtin as a top-level command: `time`, `read`,
#     `test`, `set`, `export`. (`sms read` is fine — `read` is a subcommand, not a
#     command.)
