# The Android APIs exposed to the container as commands.
#
# One name per line. `#` starts a comment; blank lines are ignored.
#
# Each name becomes:
#   * a symlink to the `android-bin` binary, so `camera ...` runs it, and
#   * an entry in the generated api_catalog.h, which is what `android-bin --list`
#     prints and what the unknown-name check reads.
#
# **This list must match the handlers Layer 1 registers.** The authority is
# `VyzorixForegroundService.buildRouter()` in android-core; this file is the
# container's view of it. A name here that the router does not serve fails at
# call time with `unknown_api`; a name the router serves that is missing here is
# simply not reachable as a command. `ApiCatalogTest` asserts the two agree.
#
# `auth` is deliberately absent: it is the reserved name the bridge serves *before*
# authentication, not a callable API, and the router refuses to register it.
#
# The design doc's "120 APIs" is the target surface, not the current one. The list
# grows as `apis/` grows; it is not padded with names nothing answers.

battery
device_info
logcat
network
session
storage
