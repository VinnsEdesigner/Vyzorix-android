## libv publishing gotcha
`compileJava` and `compileKotlin` must agree on the JVM target or Gradle rejects
the build ("Inconsistent JVM-target compatibility"). Set **both** to 17:
`kotlin.compilerOptions.jvmTarget = JVM_17` **and** `java.sourceCompatibility/
targetCompatibility = VERSION_17`.

## Lint gotchas that cost time
- **ktlint's `MaxLineLength` is 100**, and `@Suppress("X") // reason` inline pushes
  past it. Worse, ktlint rejects a line comment between a KDoc and an `@Suppress`.
  The accepted shape is a bare `@Suppress("SwallowedException")` on its own line
  directly above the declaration, with the reason folded into the KDoc above.
- **A multi-line `catch (\n @Suppress(...)\n e: T,\n)` gets mangled**: ktlint
  reorders it to `Exception: e`. Suppress at **function** level instead.
- detekt `SwallowedException` is silenced by the function-level `@Suppress`; it
  does not accept the annotation on the catch parameter cleanly here.
- detekt `MagicNumber` wants named constants for `0xFFFF`, `0xFF`, PEM width 64,
  code length 8, error-body preview 256, payload sizes 4.
- `@OptIn(ExperimentalSerializationApi::class)` is needed on the `Json { ... }`
  builder (explicitNulls).

## Gradle gotchas
- `local.properties` must exist with `sdk.dir` or the build cannot find the SDK.
- Tests live in `tests/cloud-connector/unit/kotlin`; the module's `sourceSets.test`
  points there.
- `:cloud-connector` depends on `:android-core` (`api(project(...))`) because it
  feeds the PTY broker and the bridge.

### Dead-code gate: two real bugs found and fixed
The gate only scanned `android-core/src/main`, so the new modules' dead code was
invisible. Extending it to `cloud-connector` + `app` surfaced 19 findings, and two
of them were **gate bugs**, not code bugs:
1. **Char literals.** `strip_kotlin` ran the string regex before char literals, so
   `'"'` was read as a string opener and blanked every line up to the next `"`.
   That hid two genuine uses in `RawJson.kt`. Fix: strip char literals first
   (`'(?:[^'\\\n]|\\.)'`).
2. **`${...}` expressions.** `count_interpolations` only matched `$NAME`, so
   `${ERROR_BODY_PREVIEW.length}` looked unused. Fix: scan every `${...}` block.
3. The manifest scan only read `MAIN_DIRS[0]`; now it reads every module.

Also added the OkHttp `WebSocketListener` callbacks (`onOpen`/`onMessage`/
`onClosed`/`onFailure`) to `FRAMEWORK_CALLBACKS` — the client calls them.

### 12 bugs this found that no JVM test could

Server (commits 7ce4a034, 423a04d4):
1. **Two signing schemes on one route group.** `setupDeviceManagementRoutes` chained
   the API-client middleware (`X-Signature`/`X-Client-ID`) in front of the device
   keypair middleware. A device has no client secret, so every device request 401'd
   before its own signature was checked. Split into `setupDeviceSignedRoutes` (device
   keypair only) and an operator group on the tenant group.
2. **`devices.created_at/updated_at` scanned into `time.Time`** but stored as TEXT
   -> enroll 500. Now read as a raw value and converted.
3. **`parseTimestamp` had no `time.Time` case**, so a value the driver returns as
   `time.Time` silently became the zero time. Added the case plus the driver's
   space+offset formats.
4. **`commands.created_at/updated_at` had the same scan bug** -> every command result
   failed to record. Added a `sqlTime` Scanner used at the 8 command read sites.
5. **`RespondInternalError` logged no cause** -> a 500 was undiagnosable. Now logs
   the attached error.
6. **Session cookie hardcoded `Secure: true`** -> local HTTP runs cannot authenticate
   at all. Now `COOKIE_INSECURE=true` in a dev build only.

Android (commit 92f728e):
7. **Enroll ran on the main thread** -> `NetworkOnMainThreadException` killed the
   foreground service. `start()` now does its work on a background thread.
8. **Only `CloudError` was caught**, so any `IOException` escaped the service start
   path and crashed it. Transport failures are caught now.
9. **Cleartext HTTP blocked** by the platform (Android 9+). Added a network security
   config allowing `10.0.2.2`/localhost only; the default stays TLS-required.
10. **Outbound frames lost `type`.** The shared `Json` config drops defaults and every
    outbound `type` has one, so the server had no discriminator to route by and every
    command result was silently lost. Added a defaults-keeping `CloudJson.outbound`.
11. **An already-claimed device could never fetch its config** — `ensureEnrolled`
    returned early on 409 without setting `deviceId`, which the re-fetch needs to
    sign. The id is the uuid, known from the first run.
12. **`SHELL_EXEC` argv[0] was `-c`.** The native launcher uses the argument list
    verbatim as argv, so the shell treated `-c` as its own name. argv[0] is now the
    shell path.

### Verification recipes worth keeping
- Emulator: `/opt/android-sdk/emulator/emulator -avd x86test -no-window -no-audio
  -no-boot-anim -gpu swiftshader_indirect -no-snapshot -accel off`. Boots in ~80s.
- Build the app against the server:
  `./gradlew :app:assembleDebug -PcloudBaseUrl=http://10.0.2.2:3000
  -PserverPublicKey="$(cat signing.pub.oneline)"` where the PEM has literal `\n`
  (the BuildConfig field is a Java string literal, so the escapes must stay).
- Server: `ENV=development COOKIE_INSECURE=true ENFORCE_HMAC=true
  SERVER_SIGNING_KEY_PATH=... API_KEY_primary=... JWT_SECRET=... SESSION_SECRET=...
  DATABASE_URL=... PORT=3000 ./api`. Seed an operator with a real argon2id hash
  (m=65536,t=3,p=4, salt 16, key 32, base64 std no padding) writing **Unix millis**
  for timestamps, not `time.Time` — a seeded `time.Time` is stored as TEXT and the
  repositories scan those columns as int64.
- The e2e Go client (`/tmp/e2e`) speaks the device wire contract and drives the whole
  flow; the operator session needs a CSRF token (`csrf_token` field) and the cookie
  jar must be told to keep Secure cookies over plain HTTP.
